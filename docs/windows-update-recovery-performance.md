# Windows Update: legacy recovery evidence parsing

At the end of the Python metadata query, the Windows installer proceeds to layout, executable, process, configuration and ownership checks. If the existing prefix lacks a current ownership/finalization state, it reads installed package identities and scans approved transaction evidence before constructing the main solver request.

Older approved locks can be over 100 MB because they retain full package records. The strict JSON preflight used to copy the entire remaining input into a new string at every numerical value or literal. It then ran an anchored expression on that temporary string. The resulting copying and allocations can grow quadratically even for valid, flat input. The amended validator reads JSON number, literal and Unicode-escape syntax at the current cursor without copying the suffix. Duplicate keys, nesting limits, malformed tokens and trailing input are still rejected. Recovery still requires the same prefix, configuration hash, executable hash and exact installed package identities before offering finalization.

The phase trace is written to a uniquely named `scientific-python-update-*.log` under the process temporary directory. The installer prints its actual path. It records fixed phase names, elapsed times, evidence file sizes and ordinal numbers, and sanitized failure categories. It never records the phase error message, command arguments, evidence JSON or package URLs. The phase log is separate from Micromamba's existing transaction diagnostics. Before approval, the trace announces a large recovery file before deserialization. The [five-second package progress monitor](windows-installation.md#installation-progress) starts after package approval.

For Windows acceptance, close Science/Spyder processes and deactivate Science in the calling terminal. Use `windows/00-menu.ps1` from a verified extracted candidate in Windows PowerShell 5.1 and select Install/update and the existing Home installation. Decline changes to package requests. A matching earlier transaction can produce the separate `Finish installation using those installed packages? [y/N]:` prompt rather than the solver banner. For a no-change acceptance of the fix, answer **No** at this or any package/source/finalization approval prompt; a cancellation report is expected. Save the phase log. Review a later finalization or package plan separately before approving it.
